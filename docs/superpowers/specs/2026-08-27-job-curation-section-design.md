# 채용공고 큐레이션 섹션 설계 (Job Curation)

- 작성일: 2026-08-27
- 상태: 사용자 승인된 설계
- 관련 기능: 채용공고 목록(/jobs), 매칭 엔진, 요건 비교, 커리어갭 counterfactual

## 1. 배경과 목표

워크넷 실공고 전량(6만+건, 매일 새벽 크론 갱신)이 들어오면서 목록만으로는 탐색이 어렵다.
민간 포털의 "큐레이션 JOB" UX처럼 `/jobs` 상단에 탭형 추천 카드 섹션을 얹고,
아래에 기존 검색 리스트를 유지한다. 모든 추천 기준은 기존 엔진·필드의 결정론적 산출값만 쓴다.

## 2. 화면 구조

- `/jobs` 페이지 상단에 "큐레이션 JOB" 섹션: 탭 칩(가로 스크롤) + 카드 가로 스크롤(탭당 최대 8건).
- 카드는 기존 `job-card` 컴포넌트를 재사용하고, 배지를 추가한다:
  - D-day 배지 (마감 7일 이내 빨강, `applyDeadline` 기준. 없으면 "상시채용")
  - 매칭 등급 배지 (A/B, `evaluateJobFit`) - 개인화 탭에서만
  - "OO 취득 시 지원 가능" 문구 - 자격 탭에서만
- 하단 기존 검색 리스트·필터는 변경하지 않는다.

## 3. 탭 구성과 기준 (v1, 5개)

| 탭 | 기준 | 데이터/엔진 |
|---|---|---|
| 신규 | postedAt 최근 3일, 최신순 | jobs.postedAt |
| 마감임박 | applyDeadline 오늘~D-7, 마감 가까운 순 | jobs.applyDeadline (날짜 정규화 완료) |
| 맞춤 추천 | 후보군(아래 5절) 중 evaluateJobFit 점수순, C등급 이상 | job-match 엔진 |
| 지금 지원가능 | 맞춤 추천 후보 중 필수요건(REQUIRED) NOT_SATISFIED 0건 | job-requirement-comparison |
| 자격 따면 열리는 공고 | 최근 커리어갭 분석의 1순위 부족 자격을 충족 가정한 프로필로 매칭 시 새로 지원가능(A/B)이 되는 공고 | career-gap counterfactual(buildHypotheticalProfile 로직 재사용) |

## 4. 로딩 방식

- 서버 컴포넌트(page.tsx)는 공통 탭(신규)만 미리 계산해 첫 화면에 렌더.
- 나머지 탭은 클라이언트가 탭 클릭 시 서버 액션 `getJobCurationAction(tab)` 호출로 지연 로드.
- 개인화 탭 액션은 세션 유저 기준(requireSessionUser 패턴), 클라이언트 인자로 userId를 받지 않는다.

## 5. 성능 원칙 (6만+건 대응)

- 개인화 탭은 절대 전체 jobs를 스캔하지 않는다. 후보군 축소:
  ① 유저 관심 직종코드(primary interest occupation의 jobCategoryCode) 공고
  ② 프로필 지역 공고
  를 합쳐 최신순 상위 500건으로 제한한 뒤 엔진을 돌린다.
- 요건 비교(지원가능 탭)는 맞춤 추천 상위 결과(최대 50건)에 대해서만 실행한다.
- 신규/마감임박은 전 유저 공통이므로 서버 메모리 캐시 10분(TTL) 적용.

## 6. 비로그인·데이터 부족 fallback

- 비로그인: 신규·마감임박 탭만 활성. 개인화 탭 클릭 시 로그인 유도 카드.
- 프로필/희망직무 없음: "희망직무를 설정하면 맞춤 공고를 보여드려요" CTA (시장 비교 카드와 동일 패턴).
- 커리어갭 분석 없음(자격 탭): "이력서 AI 점검 또는 커리어 진단을 먼저 해보세요" CTA.
- 탭 결과 0건: 탭은 보이되 "조건에 맞는 공고가 아직 없어요" 빈 상태 문구.

## 7. 트래킹 (영업 DB 연결)

- `curation_tab_viewed` (metadata: tab), `curation_job_clicked` (metadata: tab, jobId)를
  activity event로 기록 - 리드 신호·탭별 전환율 측정의 원천.

## 8. 에러 처리

- 큐레이션 계산 실패 시 해당 탭만 빈 상태로 표시하고 서버 로그. 목록/검색에는 영향 없음.

## 9. 테스트

- 서비스 레벨(tsx 스크립트): 탭별 산출 검증 - 신규 3일 필터, D-day 범위, 후보군 500건 상한,
  지원가능 탭의 REQUIRED 미충족 0건 보장, 자격 탭의 "가정 전 불가 → 가정 후 가능" 조건.
- 비로그인/프로필 없음 fallback 분기.

## 10. 범위 외

- 지역 맞춤·중장년 우대·급여 TOP 탭 (v2 후보)
- 매출 TOP·합격축하금 (데이터 없음)
- 홈 화면 노출(현재는 /jobs 전용)
